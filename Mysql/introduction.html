What is MySQL? — Overview

MySQL is the world's most popular open-source Relational Database Management System (RDBMS). It is backed by Oracle Corporation and widely used by top-tier tech firms like Facebook, Twitter, YouTube, and Netflix as part of the classic LAMP/LEMP stack.

Key Feature Highlights:
  • Dual-License Model: Free open-source edition (GPL) alongside paid enterprise editions.
  • Multi-threaded & High-Performance: Built to process high-throughput workloads with ease.
  • Pluggable Storage Engine Architecture: Allows developers to swap storage engines (e.g., InnoDB, MyISAM) based on application requirements.

Relational Database Fundamentals

A relational database organizes data into one or more tabular formats (tables) where columns represent attributes, and rows represent unique records. The relationships between tables are maintained using key concepts:

Primary Key (PK)

A column or group of columns that uniquely identifies a row in a table. It must contain unique values and cannot contain NULL values.

Foreign Key (FK)

A column in one table that links to a Primary Key in another table, ensuring referential integrity of data across the database relationships.

ACID Properties

To guarantee reliability and data integrity, MySQL transactions adhere to the ACID model:

Property Description
Atomicity The entire transaction succeeds or fails as a single indivisible unit ("All-or-Nothing").
Consistency A transaction brings the database from one valid state to another, maintaining all schema constraints and rules.
Isolation Concurrent execution of transactions leaves the database in the same state as if they were executed sequentially.
Durability Once committed, transaction logs are permanently flushed to non-volatile storage and survive system crashes.

SQL Commands: DDL, DML, DCL, and TCL

SQL (Structured Query Language) is divided into functional command subsets:

1. Data Definition Language (DDL)

Defines the structure/schema of the database elements.

CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

2. Data Manipulation Language (DML)

Manipulates data within existing tables.

INSERT INTO users (username, email) 
VALUES ('jerry_dev', 'jerry@example.com');

SELECT * FROM users WHERE username = 'jerry_dev';

MySQL Architecture Overview

MySQL is structured logically into three main layers:

  1. Client Layer: Handles connection administration, security authentication, and SSL setup.
  2. Server/SQL Layer: Handles query parsing, analysis, code generation, query execution plans, caching, and optimization.
  3. Pluggable Storage Engine Layer: Responsible for storing and retrieving actual physical data from files.
💡 Pro Tip: Swapping storage engines changes *how* the data is written on disk and how indexes are structured, but does not alter the SQL queries written at the application layer.

InnoDB vs MyISAM Storage Engines

The two most common storage engines in MySQL are compared below:

Feature InnoDB (Default in 5.5+) MyISAM
Transactions Yes (Fully ACID Compliant) No
Locking Level Row-level Locking (High concurrency) Table-level Locking (Low concurrency)
Foreign Keys Yes No
Crash Recovery Yes (Using Redo Logs/Doublewrite buffer) No (Requires repair tables)

Top MySQL Interview Questions & Answers
Q1: What is the difference between CHAR and VARCHAR data types?
Answer: CHAR is a fixed-length string data type. If the inserted string is shorter than the defined limit, MySQL pads it with spaces. VARCHAR is a variable-length string that consumes space matching the exact string size plus a prefix byte storing the length. Use CHAR for uniform strings (e.g. MD5 hashes, UUIDs) and VARCHAR for variable-length items.
Q2: How does MySQL handle indexing, and what index type is default?
Answer: MySQL indexes speed up query processing. In the default InnoDB engine, tables use B+ Tree indexes. The main table data is organized around the Clustered Index (Primary Key), and any secondary indexes point back to the Primary Key.
