01

Why Operators & Functions Exist

SELECT and WHERE give you the skeleton of a query. Operators and functions are what let you actually compute, compare, and reshape data instead of just fetching it raw.

Problem it solves

  • Raw column values are rarely exactly what the application needs — operators let you compute new values (salary * 1.1) and functions let you transform them (UPPER(name)).
  • Conditions in WHERE need more than plain equality — comparison and logical operators combine multiple conditions; LIKE/BETWEEN/IN/EXISTS express "fuzzy" or set-based conditions naturally.
  • Real data is messy — NULLs, inconsistent casing, unformatted dates — and built-in functions are MySQL's way of cleaning that up inside the query itself instead of in application code.

Real-world example

An e-commerce "search products" feature might combine all of this in one query: price BETWEEN 500 AND 2000, name LIKE '%phone%', category IN ('Electronics','Accessories'), and discount IS NOT NULL — four different operator families working together in a single WHERE clause.

Interview Tip

Interviewers love asking you to rewrite one operator using another — e.g. "rewrite BETWEEN using comparison operators," or "rewrite IN using OR." Being able to do this on the spot shows you understand what's happening underneath, not just the syntax.

Common Mistake

Assuming / does integer division like in Java. In MySQL, 10 / 4 returns 2.5000, not 2. If you need integer division, use DIV: 10 DIV 4 → 2.

Warning

Division by zero in MySQL returns NULL by default, not an error and not infinity — a very common trick question.

Comparison Operators

Used to compare two values and always evaluate to TRUE, FALSE, or — critically — UNKNOWN when NULL is involved.

OperatorMeaningNULL-safe?

Interview Tip

NULL = NULL evaluates to NULL (not TRUE!) because NULL means "unknown," and unknown compared to unknown is still unknown. Only IS NULL or the NULL-safe operator <=> can correctly test for NULL.

04

Logical Operators

Combine multiple conditions: AND, OR, NOT, and MySQL's XOR.

logical_example.sql
SELECT * FROM employee
WHERE department = 'Engineering' AND salary > 50000;

SELECT * FROM employee
WHERE NOT (department = 'Sales');

Truth Table — Three-Valued Logic

MySQL logic isn't just TRUE/FALSE — NULL introduces a third state, UNKNOWN, which behaves specially in AND/OR.

ABA AND BA OR B
TRUENULLNULLTRUE
FALSENULLFALSENULL
NULLNULLNULLNULL
Why This Matters

A WHERE clause only keeps rows where the condition is TRUE — rows that evaluate to FALSE or UNKNOWN are both excluded. This is why filters silently drop NULL-containing rows even when your logic "looks" correct.

06

LIKE — Pattern Matching

Matches strings against a pattern using two wildcards: % (zero or more characters) and _ (exactly one character).

like_examples.sql
SELECT * FROM employee WHERE name LIKE 'A%';      -- starts with A
SELECT * FROM employee WHERE name LIKE '%a';      -- ends with a
SELECT * FROM employee WHERE name LIKE '%an%';    -- contains 'an'
SELECT * FROM employee WHERE name LIKE '_sha';    -- exactly 1 char + 'sha'
Performance Note

A leading wildcard, e.g. LIKE '%an', prevents MySQL from using a standard B-Tree index and forces a full table scan. LIKE 'A%' (leading fixed text) can still use an index.

07

BETWEEN — Range Checks

A shorthand for a closed, inclusive range check.

between_example.sql
SELECT * FROM employee WHERE salary BETWEEN 30000 AND 60000;

-- exactly equivalent to:
SELECT * FROM employee WHERE salary >= 30000 AND salary <= 60000;
Interview Tip

BETWEEN is inclusive on both ends — a very common gotcha question is whether 30000 and 60000 themselves are included (yes, both are).

08

IN — Set Membership

Checks whether a value matches any value in a list or the result of a subquery.

in_example.sql
SELECT * FROM employee
WHERE department IN ('Engineering', 'Sales', 'HR');

-- with a subquery
SELECT * FROM employee
WHERE department_id IN (SELECT id FROM department WHERE active = 1);
Warning

NOT IN with a list or subquery that can contain NULL returns an empty result set — a classic silent bug. Prefer NOT EXISTS when NULLs might be present.

09

EXISTS — Subquery Presence Check

Returns TRUE if a correlated subquery returns at least one row — MySQL stops scanning as soon as it finds one match.

exists_example.sql
SELECT d.name
FROM department d
WHERE EXISTS (
  SELECT 1 FROM employee e WHERE e.department_id = d.id
);

Comparison: IN vs EXISTS

AspectINEXISTS
Subquery typeUsually non-correlatedCorrelated (references outer query)
Stops early?Materialises full list firstShort-circuits on first match
NULL safetyUnsafe with NOT IN + NULLsSafe — no NULL surprises
Best forSmall, static listsLarge tables, existence checks

String Functions

MySQL's most-used text manipulation toolkit.

CONCAT()LENGTH()UPPER() / LOWER() SUBSTRING()TRIM()REPLACE() LEFT() / RIGHT()LOCATE()LPAD() / RPAD()
string_functions.sql
SELECT CONCAT(first_name, ' ', last_name) AS full_name,
       UPPER(email) AS email_upper,
       LENGTH(name) AS name_len,
       SUBSTRING(phone, 1, 3) AS area_code,
       TRIM('  Asha  ') AS clean_name
FROM employee;
full_nameemail_uppername_lenarea_code
Asha RaoASHA.RAO@MAIL.COM8044
Common Mistake

MySQL's SUBSTRING is 1-indexed, not 0-indexed like Java's substring() — SUBSTRING('Hello', 1, 2) returns 'He', starting from position 1.

11

Date Functions

Extract, compute, and format date/time values — essential for reports, audit logs, and scheduling logic.

NOW() / CURDATE()DATEDIFF()DATE_ADD() / DATE_SUB() DATE_FORMAT()YEAR() / MONTH() / DAY()TIMESTAMPDIFF()
date_functions.sql
SELECT name,
       DATEDIFF(CURDATE(), joining_date) AS days_employed,
       DATE_FORMAT(joining_date, '%d-%b-%Y') AS pretty_date,
       DATE_ADD(joining_date, INTERVAL 1 YEAR) AS first_anniversary
FROM employee
WHERE YEAR(joining_date) = 2023;
Best Practice

Avoid wrapping an indexed date column in a function inside WHERE (e.g. YEAR(joining_date) = 2023) in performance-critical queries — it disables index usage. Prefer a range: joining_date BETWEEN '2023-01-01' AND '2023-12-31'.

12

NULL-Handling Functions

NULL means "unknown" — these functions are how MySQL lets you handle that gracefully instead of writing verbose CASE logic everywhere.

null_functions.sql
SELECT name,
       IFNULL(commission, 0) AS commission_safe,
       COALESCE(phone, alt_phone, 'N/A') AS contact,
       NULLIF(discount, 0) AS real_discount
FROM employee
WHERE manager_id IS NOT NULL;
FunctionBehaviour
IS NULL / IS NOT NULLThe only correct way to test for NULL — = NULL never works
IFNULL(a, b)Returns b if a is NULL, else a (MySQL-specific, 2 args)
COALESCE(a, b, c...)Returns the first non-NULL value in the list — standard SQL, any number of args
NULLIF(a, b)Returns NULL if a = b, else returns a — useful for avoiding divide-by-zero
13

Common Mistakes & Performance Notes

Using = NULL instead of IS NULL ▾
Always evaluates to UNKNOWN, so the row is never matched — one of the single most common fresher bugs in WHERE clauses.
Leading-wildcard LIKE on large tables ▾
LIKE '%term' can't use a standard index — for real search, consider MySQL full-text indexes instead.
NOT IN with a NULL-containing subquery ▾
Silently returns zero rows instead of erroring, because comparing anything to NULL with NOT IN produces UNKNOWN for every row.
Wrapping indexed columns in functions inside WHERE ▾
e.g. WHERE YEAR(created_at) = 2024 forces a full scan. Use a range comparison on the raw column instead.
Forgetting that string comparisons can be case-insensitive by default ▾
MySQL's default collation is often case-insensitive, so 'Asha' = 'asha' may return TRUE unless the column uses a case-sensitive (_bin or _cs) collation.

IN vs EXISTS vs JOIN

  • You have a small, fixed, known list of literal values.
  • Readability matters more than micro-optimisation for a tiny table.
  • You only need to know whether related rows exist — not their actual data.
  • The subquery may contain NULLs, where NOT IN would be unsafe.
  • The inner table is large — EXISTS can short-circuit on first match.
  • You actually need columns from both tables in the result set.
  • You're aggregating across the relationship (COUNT, SUM per group).

Memory Tricks

Precedence

"My Aunt Called, Not Angry, Or" → * (Multiply) → + (Add) → Comparison → NOT → AND → OR.

LIKE Wildcards

"% is many, _ is uno" → % = zero-or-more characters, _ = exactly one character.

NULL Functions

"COALESCE Collects, NULLIF Nullifies" → COALESCE picks first non-null; NULLIF turns a match into NULL.

SELECT d.name FROM department d

Summary

Arithmetic operators compute; comparison and logical operators filter, with NULL introducing three-valued logic that trips up most freshers. LIKE, BETWEEN, IN, and EXISTS each express a different shape of condition — pattern, range, list, and existence — and choosing the right one is both a readability and a performance decision. String, date, and NULL functions round out the toolkit MySQL gives you to clean and reshape data without leaving the database. Spring Boot mirrors almost all of this through derived query method names and JPQL, but native SQL is still the fallback whenever a function needs to run inside the database itself.
