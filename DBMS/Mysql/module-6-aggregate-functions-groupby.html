Aggregate Functions & GROUP BY

Raw rows don't answer business questions. "Total revenue by region," "average salary per department," "top 5 products this month" — every dashboard your Java backend feeds is built on COUNT, SUM, AVG, MAX, MIN, GROUP BY, and HAVING.

Why this module exists

Every "report" question is an aggregation question

"How many orders today?" "What's our average order value?" "Which region sold the most?" Interviewers deliberately phrase these as business questions to see whether you can translate them into COUNT/SUM/AVG + GROUP BY + HAVING without hand-holding.

Real-world analogy

GROUP BY is like sorting a pile of receipts into labeled envelopes — one envelope per department, per month, per product. Aggregate functions are what you calculate after sorting: total per envelope, average per envelope, biggest single receipt per envelope.

Problem it solves

Without aggregation, you'd have to pull every raw row into your Java service and sum/count/average it in application code — slow, memory-heavy, and exactly the kind of work a database engine is built to do far more efficiently at the storage layer.

01 · Function

COUNT

Counts rows — but which variant you use changes what gets counted, a classic interview trap.

count.sql
SELECT COUNT(*) FROM employees;                    -- all rows, including NULLs anywhere
SELECT COUNT(phone) FROM employees;             -- only rows where phone IS NOT NULL
SELECT COUNT(DISTINCT dept_id) FROM employees; -- unique department count
→ COUNT(*) = 120 total rows
→ COUNT(phone) = 87 (33 rows have NULL phone)
→ COUNT(DISTINCT dept_id) = 6 unique departments
FormCounts
COUNT(*)Every row, regardless of NULLs in any column
COUNT(column)Only rows where that column is NOT NULL
COUNT(DISTINCT column)Unique non-NULL values in that column
Interview trap

"Is COUNT(*) slower than COUNT(1)?" — In modern MySQL/InnoDB, they perform identically; the optimizer treats them the same. This used to matter in very old engines but is a myth today — say so confidently.

01Interview questions

Does COUNT(column) include NULL values?+

No — COUNT on a specific column skips rows where that column is NULL. Only COUNT(*) counts every row unconditionally.

Scenario: How do you count how many distinct customers placed an order last month? Scenario+

SELECT COUNT(DISTINCT customer_id) FROM orders WHERE order_date >= '2026-06-01' AND order_date < '2026-07-01';

02 · Function

SUM

Totals a numeric column across a group of rows — the backbone of every revenue and total-cost report.

sum.sql
SELECT SUM(amount) AS total_revenue
FROM orders
WHERE order_date >= '2026-01-01';
→ total_revenue = 1,842,350.00
→ SUM ignores NULL values automatically; SUM over zero rows returns NULL, not 0
Common mistake

Assuming SUM(amount) returns 0 when no rows match. It actually returns NULL — wrap it with COALESCE(SUM(amount), 0) if your Java code expects a numeric default.

Spring Boot relation

A @Query("SELECT SUM(o.amount) FROM Order o WHERE ...") JPQL method returning a BigDecimal must handle a possible null result the same way — a very common NPE source for freshers.

03 · Function

AVG

The mean of a numeric column — quietly skips NULLs, which changes the denominator in ways people forget.

avg.sql
SELECT AVG(salary) AS avg_salary FROM employees;

-- vs manually computing SUM / COUNT(*) — these can differ!
SELECT SUM(salary) / COUNT(*) AS manual_avg FROM employees;
→ AVG(salary) divides SUM(salary) by COUNT(salary) — NULL salaries excluded from both
→ SUM(salary)/COUNT(*) divides by ALL rows including NULL-salary ones — can give a different, lower number
Interview trap

AVG(column) is not the same as SUM(column)/COUNT(*) if the column has NULLs — AVG's internal denominator is COUNT(column), which excludes NULLs, while COUNT(*) counts every row.

04 · Functions

MAX / MIN

The highest and lowest values in a column — work on numbers, dates, and even strings (lexicographic order).

max_min.sql
SELECT MAX(salary) AS highest_paid,
       MIN(salary) AS lowest_paid,
       MAX(hire_date) AS most_recent_hire
FROM employees;
→ highest_paid = 98000.00, lowest_paid = 32000.00
→ most_recent_hire = 2026-05-14 (MAX works on DATE/DATETIME too)
Interview tip

MAX/MIN on an indexed column can often be answered instantly by MySQL by reading just one end of the B+Tree — no full scan needed. Watch for "Select tables optimized away" in EXPLAIN output as proof.

01Interview questions

Scenario: Find the employee(s) with the highest salary in each department. Scenario+

A plain MAX(salary) with GROUP BY only gives the value, not the employee row. You need either a correlated subquery, a self-join comparing to the per-department MAX, or a window function: RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) (MySQL 8+).

05 · Clause

GROUP BY

Collapses many rows into one row per distinct group — the mechanism every aggregate function above actually relies on.

group_by.sql
SELECT dept_id,
       COUNT(*) AS headcount,
       AVG(salary) AS avg_salary,
       SUM(salary) AS total_payroll
FROM employees
GROUP BY dept_id;

01How MySQL works internally

1

Rows filtered by WHERE first

Only qualifying rows enter the grouping stage — WHERE runs before GROUP BY.

2

Rows bucketed by group key

MySQL either sorts rows by the GROUP BY columns, or (often faster) builds an in-memory hash table keyed by the group values.

3

Aggregate functions computed per bucket

COUNT/SUM/AVG/MAX/MIN accumulate as each row streams into its bucket.

4

HAVING filters the buckets

Only after aggregation is complete does HAVING remove entire groups that don't qualify.

Beginner mistake — SELECT list rule

Every non-aggregated column in SELECT must appear in GROUP BY. SELECT dept_id, first_name, COUNT(*) FROM employees GROUP BY dept_id is invalid/ambiguous — MySQL's default strict mode (ONLY_FULL_GROUP_BY, on since 5.7) will reject it.

02Multi-column grouping

group_multi.sql
SELECT dept_id, YEAR(hire_date) AS hire_year, COUNT(*) AS hires
FROM employees
GROUP BY dept_id, YEAR(hire_date);
→ One row per unique (dept_id, hire_year) combination — grouping on multiple columns forms a compound key
06 · Clause

HAVING

WHERE for groups. The single most common WHERE-vs-HAVING confusion in fresher interviews.

having.sql
SELECT dept_id, COUNT(*) AS headcount, AVG(salary) AS avg_salary
FROM employees
WHERE status = 'ACTIVE'
GROUP BY dept_id
HAVING COUNT(*) > 5 AND AVG(salary) > 50000
ORDER BY avg_salary DESC;
→ WHERE removes inactive employees BEFORE grouping
→ HAVING then removes entire departments whose group didn't meet the aggregate thresholds
AspectWHEREHAVING
Operates onIndividual rowsAggregated groups
RunsBefore GROUP BYAfter GROUP BY / aggregation
Can use aggregate functionsNoYes — that's its whole purpose
Can use column aliasesNoYes (in MySQL specifically)
Interview trap

"Can you write WHERE COUNT(*) > 5?" — No. Aggregate functions aren't computed yet when WHERE runs; that's precisely why HAVING exists as a separate, later filtering stage.

Best practice

Filter as much as possible in WHERE before grouping, and use HAVING only for conditions that genuinely depend on the aggregate result — this lets MySQL discard rows early and group fewer of them.

01Interview questions

Asked at TCS Digital: Write a query to find departments with more than 10 employees. TCS Digital+

SELECT dept_id, COUNT(*) FROM employees GROUP BY dept_id HAVING COUNT(*) > 10;

Scenario: Find customers who placed more than 3 orders with a total spend over ₹10,000. Scenario+

SELECT customer_id, COUNT(*) AS order_count, SUM(amount) AS total_spend FROM orders GROUP BY customer_id HAVING COUNT(*) > 3 AND SUM(amount) > 10000;

02Common report patterns to memorize

"Top spending customer per city" — needs a window function (MySQL 8+) or a correlated subquery, since plain GROUP BY only returns aggregate values, not the specific row that produced the max.

SELECT * FROM (
  SELECT city, customer_id, SUM(amount) AS total,
         RANK() OVER (PARTITION BY city ORDER BY SUM(amount) DESC) AS rnk
  FROM orders GROUP BY city, customer_id
) ranked WHERE rnk = 1;

"Products with fewer than 10 units left in stock across all warehouses" — an aggregate threshold filtered with HAVING after summing.

SELECT product_id, SUM(stock) AS total_stock
FROM inventory GROUP BY product_id
HAVING SUM(stock) < 10;

"What % of total revenue does each region contribute?" — combine a group aggregate with a scalar subquery for the grand total.

SELECT region, SUM(amount) AS region_total,
       ROUND(SUM(amount) / (SELECT SUM(amount) FROM orders) * 100, 2) AS pct_of_total
FROM orders GROUP BY region;
Interview tip

When an interviewer describes a report in plain English, silently map it: "grouped by ___" → GROUP BY column, "total/average/count of ___" → aggregate function, "only show groups where ___" → HAVING, "only show rows where ___" → WHERE.

03Interview questions

Asked at Accenture: Write a query showing total sales per product category, sorted highest first. Accenture+

SELECT category, SUM(amount) AS total_sales FROM orders GROUP BY category ORDER BY total_sales DESC;

Scenario: Find the average order value per customer, but only for customers with at least 5 orders. Scenario+

SELECT customer_id, AVG(amount) AS avg_order_value FROM orders GROUP BY customer_id HAVING COUNT(*) >= 5;

Cheat Sheet

cheatsheet.sql
SELECT COUNT(*), COUNT(col), COUNT(DISTINCT col) FROM t;
SELECT SUM(col), AVG(col), MAX(col), MIN(col) FROM t;

SELECT g, COUNT(*) FROM t
WHERE cond              -- filters rows first
GROUP BY g
HAVING COUNT(*) > 5    -- filters groups after aggregation
ORDER BY COUNT(*) DESC;

-- % of total pattern
SELECT g, SUM(col)/(SELECT SUM(col) FROM t)*100 FROM t GROUP BY g;

Wrap-up

Summary & Revision Notes

COUNT

COUNT(*) counts all rows; COUNT(col) skips NULLs; COUNT(DISTINCT col) counts unique non-NULL values.

SUM / AVG

Both ignore NULLs; SUM over zero rows returns NULL, not 0 — guard with COALESCE.

MAX / MIN

Work on numbers, dates, and strings; fast on an indexed column.

GROUP BY

Collapses rows into one row per group; every non-aggregated SELECT column must appear in it.

HAVING

Filters groups after aggregation — the only place aggregate functions can appear in a filter condition.

Reports

Translate plain-English asks directly: "total/avg/count of X" → aggregate, "grouped by Y" → GROUP BY, "only groups where" → HAVING.

Before your interview

Be ready to write a full GROUP BY + HAVING report from a one-sentence business ask on the spot, and explain clearly why WHERE can't filter on an aggregate value.
