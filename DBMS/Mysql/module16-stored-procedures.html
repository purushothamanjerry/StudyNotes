01

Why Stored Procedures Exist

A stored procedure is a named, precompiled block of SQL (with procedural logic) stored inside the database itself and invoked with a single CALL.

Problem it solves

  • Complex multi-step operations (validate → update → log → notify) can live in one place instead of being scattered across application code.
  • Reduces network round-trips — one CALL instead of five separate queries sent from the application.
  • Centralises business logic that many different applications or scripts might need to share consistently.

Real-world example

A "process month-end payroll" operation might need to loop through every employee, calculate tax, update balances, and write an audit log — all as one atomic, reusable unit that any internal tool can trigger with CALL ProcessPayroll('2025-01').

Interview Tip

Interviewers often ask you to contrast a stored procedure with a plain SQL query: a query retrieves/modifies data; a stored procedure is a full programmable unit with variables, conditionals, and loops — closer to a mini function than a single statement.

02

CREATE PROCEDURE

Defines a new stored procedure. Because procedure bodies contain semicolons internally, MySQL needs a temporary delimiter change to parse them correctly.

create_procedure.sql
DELIMITER $$

CREATE PROCEDURE GreetEmployee()
BEGIN
  SELECT 'Hello from a stored procedure!';
END$$

DELIMITER ;

CALL GreetEmployee();
Common Mistake

Forgetting DELIMITER $$ before the procedure and DELIMITER ; after. Without it, MySQL sees the first internal semicolon and thinks the statement is finished — causing a syntax error.

03

Parameters

Stored procedures accept three kinds of parameters, each with a different data flow direction.

TypeDirectionUse Case
IN (default)Caller → ProcedurePass a value in — the procedure can't change what the caller sees
OUTProcedure → CallerReturn a computed result back to the caller via a session variable
INOUTBoth directionsCaller passes a value in, procedure modifies it, caller sees the new value
parameters_example.sql
CREATE PROCEDURE GetTotalSalary(
  IN dept_id INT,
  OUT total DECIMAL(12,2)
)
BEGIN
  SELECT SUM(salary) INTO total
  FROM employee WHERE department_id = dept_id;
END$$

CALL GetTotalSalary(3, @result);
SELECT @result;
04

Variables

Declared inside the procedure body with DECLARE, and assigned with SET or SELECT ... INTO.

variables_example.sql
CREATE PROCEDURE ShowTaxSlab(IN income DECIMAL(10,2))
BEGIN
  DECLARE tax_rate DECIMAL(5,2) DEFAULT 0;

  SET tax_rate = 10.0;
  SELECT income * tax_rate / 100 AS tax_amount;
END$$
Warning

All DECLARE statements must appear at the very top of a BEGIN...END block, before any other statement — declaring a variable mid-procedure is a syntax error.

05

IF

Procedural branching — note this is different from the IF() function usable inside a plain SQL expression.

if_example.sql
IF salary >= 80000 THEN
  SET tier = 'PLATINUM';
ELSEIF salary >= 50000 THEN
  SET tier = 'GOLD';
ELSE
  SET tier = 'STANDARD';
END IF;
Common Mistake

Writing ELSE IF (two words) — MySQL's procedural syntax requires ELSEIF as one word. Two words will raise a syntax error.

06

CASE

An alternative to chained IF/ELSEIF for cleaner multi-branch logic — comes in two forms.

case_example.sql
-- Simple CASE (matches an exact value)
CASE department_id
  WHEN 1 THEN SET dept_name = 'Engineering';
  WHEN 2 THEN SET dept_name = 'Sales';
  ELSE SET dept_name = 'Unknown';
END CASE;

-- Searched CASE (evaluates conditions, like IF/ELSEIF)
CASE
  WHEN salary >= 80000 THEN SET tier = 'PLATINUM';
  WHEN salary >= 50000 THEN SET tier = 'GOLD';
  ELSE SET tier = 'STANDARD';
END CASE;
Interview Tip

The procedural CASE ... END CASE statement (which runs SET/other statements) is distinct from the CASE expression you'd use inline inside a SELECT list — same keyword, two different contexts.

07

Loops

MySQL's procedural language offers three looping constructs: WHILE, REPEAT, and LOOP.

DECLARE i INT DEFAULT 1;
WHILE i <= 5 DO
  INSERT INTO log_table (msg) VALUES (CONCAT('Row ', i));
  SET i = i + 1;
END WHILE;

Checks the condition before every iteration — may run zero times.

DECLARE i INT DEFAULT 1;
REPEAT
  INSERT INTO log_table (msg) VALUES (CONCAT('Row ', i));
  SET i = i + 1;
UNTIL i > 5
END REPEAT;

Checks the condition after every iteration — always runs at least once.

my_loop: LOOP
  SET i = i + 1;
  IF i > 5 THEN
    LEAVE my_loop;
  END IF;
END LOOP my_loop;

A bare, unconditional loop — you must explicitly LEAVE it, giving you full manual control over exit timing.

Common Mistake

Forgetting to update the loop control variable (like SET i = i + 1) — creates an infinite loop that will hang the connection until manually killed.

09

Common Mistakes & Performance Notes

Forgetting DELIMITER before/after the procedure body ▾
MySQL's client interprets the first semicolon inside the body as the end of the CREATE statement unless the delimiter is temporarily changed.
Declaring variables after other statements ▾
All DECLARE statements must be the very first statements inside a BEGIN...END block.
Writing "ELSE IF" instead of "ELSEIF" ▾
MySQL's procedural IF syntax requires ELSEIF as a single keyword — two words causes a syntax error.
Infinite loops from a forgotten increment ▾
WHILE/REPEAT/LOOP all need the loop-control variable updated inside the body, or the condition never changes and the connection hangs.
Overusing stored procedures for simple CRUD ▾
A single INSERT or SELECT rarely needs a stored procedure wrapper — the added complexity outweighs the benefit for trivial operations.

Spring Boot Relation

Calling a stored procedure from Spring Data JPA.

EmployeeRepository.java
@Procedure(procedureName = "GetTotalSalary")
BigDecimal getTotalSalary(@Param("dept_id") Integer deptId);

Or, for full control (especially with OUT parameters), Spring often falls back to JdbcTemplate with a CallableStatement to invoke procedures directly via JDBC.

Warning

Business logic buried in stored procedures is invisible to Java-based code review, version control diffs, and unit tests in the same way application code is — many teams deliberately minimise procedure logic for this reason.

11

Advantages & Disadvantages

  • Performance — precompiled and cached execution plan; fewer network round-trips since multiple statements run as one CALL.
  • Security — you can grant EXECUTE on a procedure without granting direct table access, tightly controlling what callers can do.
  • Consistency — the same validated logic runs identically regardless of which application or script calls it.
  • Reduced data transfer — heavy computation happens where the data lives, instead of pulling rows to the application first.
  • Poor portability — procedural SQL syntax is vendor-specific; migrating databases means rewriting all of it.
  • Harder to version control and test — less mature tooling compared to unit-testing Java/Spring code.
  • Scales the database, not the application — heavy logic in procedures pushes CPU load onto the database server, which is usually harder to horizontally scale than application servers.
  • Debugging is harder — no rich IDE step-through debugging compared to application-layer code (which is exactly what this module's tracer above is simulating conceptually).
Interview Tip

Modern product-company teams generally keep business logic in the application layer (Spring services) and reserve stored procedures for narrow, performance-critical, or security-sensitive operations — being able to articulate this trade-off well is often more impressive than knowing the syntax.

12

Memory Tricks

Parameter Directions

"IN comes In, OUT goes Out, INOUT does both" — the name literally describes the data flow.

WHILE vs REPEAT

"WHILE checks first, REPEAT checks last" — REPEAT always runs at least once, WHILE might run zero times.

DELIMITER

"Change the fence before building, put it back after" — DELIMITER $$ before, DELIMITER ; after the procedure body.

SQL Practice Questions

Write a procedure that gives a raise percentage based on years of service using IF ▾
CREATE PROCEDURE RaisePercent(IN years INT, OUT pct DECIMAL(4,2))
BEGIN
  IF years >= 5 THEN
    SET pct = 10.00;
  ELSEIF years >= 2 THEN
    SET pct = 5.00;
  ELSE
    SET pct = 2.00;
  END IF;
END$$
Write a procedure using WHILE to insert 5 sample audit rows ▾
CREATE PROCEDURE SeedAuditLog()
BEGIN
  DECLARE i INT DEFAULT 1;
  WHILE i <= 5 DO
    INSERT INTO audit_log (msg) VALUES (CONCAT('Seed row ', i));
    SET i = i + 1;
  END WHILE;
END$$
Use CASE to map a status code to a readable label ▾
CASE status_code
  WHEN 1 THEN SET label = 'Pending';
  WHEN 2 THEN SET label = 'Approved';
  WHEN 3 THEN SET label = 'Rejected';
  ELSE SET label = 'Unknown';
END CASE;

Summary

A stored procedure is a named, reusable block of procedural SQL stored inside the database, invoked with CALL. It accepts IN, OUT, and INOUT parameters; declares local variables with DECLARE; branches with IF/ELSEIF/ELSE or CASE; and iterates with WHILE, REPEAT, or LOOP. The real interview differentiator isn't syntax memorisation — it's being able to discuss when procedures genuinely help (performance-critical, security-scoped, shared logic) versus when they hurt (portability, testability, scaling the database instead of the application).
