01 · Orientation

Why this module exists

Most fresher candidates can write a SELECT and a JOIN, but interviewers filter on the next layer: do you know what makes PostgreSQL a different engine, not just "SQL with a different name"? That's exactly the layer this module targets.

The problem this module solves
Freshers often memorize syntax but freeze when asked "why does Postgres use JSONB instead of JSON?" or "what happens internally when two transactions update the same row?" This module trains the why, not just the how.
Real-world framing
Think of an e-commerce backend: MVCC lets two customers check a product page while one buys the last unit; JSONB stores flexible product attributes; a materialized view powers the "Today's Sales" dashboard without slowing down checkout.
